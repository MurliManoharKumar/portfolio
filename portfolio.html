DevOps Task Manager Completed

A full-stack task management app with a React frontend and a Node.js backend, connected to MongoDB Atlas. Containerized both services with Docker, wrote separate development and production Docker Compose configs, served the frontend through Nginx, and pushed the built images to Docker Hub. Role: Full-Stack & DevOps.

Problem

Needed a simple, self-hosted way to create, prioritize and track tasks — and a real full-stack app to practice deploying the way it'd actually run in production, not just on localhost.

Solution

Built a CRUD task app (create, edit, mark complete, delete, filter by status/priority), then containerized the frontend and backend separately so each could be built, tagged and deployed independently.

My Contribution

Built the React UI and the Node.js API end to end, wrote the Dockerfiles and both the development and production Docker Compose files, configured Nginx for the frontend container, connected the backend to MongoDB Atlas, and pushed the images to Docker Hub.

Challenges & Troubleshooting

My first production-style container setup mixed the Vite development server with the Nginx runtime, so the frontend image was not serving the built application correctly. I split the flow into a build stage and a lightweight Nginx stage, then mounted the backend environment values through Compose instead of baking them into the image. I verified the fix by checking the browser response, the container logs and the backend's MongoDB connection output before tagging and pushing the images.

Result

Frontend and backend run as separate containers defined by a production Compose file, both images built and verified running in Docker Desktop, with the deployment prep committed and pushed to GitHub.

Browser ↓ Nginx (frontend container, port 80) ↓ Node.js API (backend container) ↓ MongoDB Atlas (cloud)
React Node.js MongoDB Atlas Docker Docker Compose Nginx Docker Hub Git
